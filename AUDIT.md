# Технический аудит — 23 сентября 2026

Проверен репозиторий на базе `649470a`: восемь HTML-страниц, общие и кейсовые
стили, весь браузерный JavaScript, серверная функция лайков, ресурсы, конфигурация,
тесты, утилита изображений и ссылки локального превью. Исправления находятся
в рабочей копии; публикация в рамках аудита не выполнялась.

## Critical

Критических уязвимостей или препятствий для работы основной части сайта не найдено.
Обнаружены и исправлены реальные дефекты:

- Страница 404 использовала относительные пути: при выдаче на `/missing/nested/path`
  браузер запрашивал стили, изображения, JavaScript и CV из неверного каталога.
- Кнопки скрытого просмотрщика изображений оставались доступны через Tab.
  Открытое окно позволяло увести фокус в фон, закрытие не возвращало фокус к изображению.
- Утилита конвертации сначала перезаписывала существующий WebP, а затем могла удалить
  его, если результат был больше исходника. Повторный запуск мог сломать уже опубликованную ссылку.

В текущих исходниках нет обнаруженных секретов; проверены также 144 текстовых
объекта из 34 коммитов локальной истории Git по шаблонам ключей AWS, GitHub,
`sk-…` и приватных ключей. Это не гарантия обнаружения произвольных секретов.
В истории env-файлов найден только пустой `.env.example`. Действующие переменные
Vercel и Redis не запрашивались и в отчёт не попадали.

## Fixed

- Корневые пути ко всем локальным ресурсам на 404.
- Просмотрщик: `inert` в закрытом состоянии, недоступный фон при открытии,
  удержание Tab/Shift+Tab, возврат фокуса после Escape/закрытия. Поведение соответствует
  [рекомендациям WAI для модальных окон](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).
- Один доступный h1 на каждой странице; новые h1 на 404, профессиональном пути
  и личной истории визуально скрыты и используют существующие названия.
- Существующие подписи разделов кейсов получили роль заголовка второго уровня;
  заголовки записей профессионального пути и отзывов стали h2 с прежними стилями.
- Конвертер проверяет временный WebP до замены действующего файла; добавлена защита
  от деления на ноль в итоговой статистике.
- `.vercelignore` исключает превью, инструменты, тесты, отчёты и пример env из
  публикации. Это штатный механизм [Vercel](https://vercel.com/docs/deployments/vercel-ignore).
- Python-кеш исключён из Git.

## Removed

Удалено девять файлов, всего **1 206 030 байт (1,15 МиБ)**. Для каждого проверены
ссылки в HTML, CSS, JS, инструментах, документации и локальном превью.
Удалены четыре неиспользуемых шрифта и пять устаревших изображений/заглушек.

Удалены CSS-блоки `.badge`, `.case-section-final`, устаревшие правила заголовка
раздела `.resume h2`, а также два неиспользуемых промежуточных значения шейдера.
Текущие два ALS-шрифта и лицензия эффекта сохранены.

Массовая автоматическая очистка была отклонена проверкой безопасности из-за риска
ошибок эвристического поиска. Вместо неё выполнены перечисленные точечные изменения
с дополнительной проверкой ссылок и сравнением в браузере. Другие CSS-кандидаты
автоматически не удалялись.

## Performance

- Уменьшен набор ресурсов репозитория/публикации; удалён небольшой объём мёртвого CSS.
- Неиспользуемые файлы и раньше не загружались страницами, поэтому удаление 1,15 МиБ
  **не означает** такое же сокращение загрузки страницы. Замер ускорения не заявляется.
- Сохранены WebP/AVIF, адаптивные обложки, lazy loading, локальные шрифты с `font-display: swap`.
- Лучи уже приостанавливаются вне экрана/в скрытой вкладке и учитывают reduced motion.
- Изображения не пережимались, качество, анимации и параметры эффекта сохранены.
- Среди используемых ресурсов остаются фото около 0,5–0,7 МБ и большая PNG-диаграмма.
  Их дальнейшее сжатие требует отдельного визуального сравнения читаемости.

## Architecture / Code quality

Это статический многостраничный сайт, а не React-приложение. package.json,
lockfile, npm-зависимостей, JSX/TSX, hooks, state/useEffect и клиентского роутера нет.
Проверки prop drilling, key и re-render здесь неприменимы. Node API использует
встроенные модули; Pillow нужен только ручной Python-утилите. Новых библиотек нет.

Плоская структура приемлема для восьми страниц; внедрение сборщика/компонентного
фреймворка не оправдано. Повторяющиеся footer/nav оставлены: переход на шаблоны
сейчас добавил бы процесс сборки ради небольшой экономии разметки.

Добавлен `scripts/check-site.py`: проверяет ссылки, якоря, CSS-ресурсы, alt,
повторные ID, безопасные ссылки с target, базовые метаданные и синтаксис JS.
README описывает запуск, ограничения локального сервера, тесты и архитектуру.
Вспомогательная проверка не является полноценным HTML/CSS/WCAG-валидатором.

Браузерный `innerHTML` используется только для постоянной разметки, без внешних
данных. Лайки проверяют case ID, тип состояния, метод и content type; идентификатор
хранится в HttpOnly/SameSite-cookie, запросы имеют таймауты, запись идемпотентна.
Секрет Redis остаётся только на сервере. Диагностический `console.warn` при сбое
WebGL сохранён: это обработчик реальной ошибки, не забытый `console.log`.

## Remaining recommendations

1. Указать основной публичный домен и добавить canonical, Open Graph и sitemap
   с абсолютными production-URL. Сейчас title/description есть на всех семи
   контентных страницах, favicon настроен, noindex стоит только на 404.
   robots.txt отсутствует — это не запрет индексации. Доменные URL не выдумывались.
2. Дополнительно разобрать кандидатов на неиспользуемые CSS-правила, например
   группы blueprint, journey, decision-table, matrix, старого profile.
   Для их массового удаления нужна проверка всех состояний, включая локальный preview.
3. Исходные PNG/JPEG сохранены для повторной конвертации. Их можно перенести в
   отдельный каталог исходников и исключить из доставки после согласованного
   изменения утилиты. Это экономия хранения/публикации, а не текущей загрузки страницы.
4. `ui-shot-4.webp` и `ui-shot-5.webp` используются локальным `previews/light-rays/`,
   поэтому не удалены. Сам каталог был незакоммичен до аудита и не менялся.
5. Лайки считаются по cookie и допускают создание новых идентификаторов: это не
   уникальные авторизованные пользователи. При реальном злоупотреблении рассмотреть
   rate limit/WAF. Новую авторизацию и изменение сценария не добавляли.
6. Проверить Safari/Firefox, скринридер и реальные показатели Core Web Vitals
   отдельно; данный прогон охватывает Chromium на двух ширинах, а не все среды.
