# Portfolio site

## Структура и запуск

Статический сайт: восемь HTML-страниц в корне, общие `styles.css` и
`back-to-top.js`, стили кейсов в `case-study.css`. `site-loader.js` отвечает
за загрузочный экран, `assets/light-rays/` — за фон главной страницы.
`api/likes.js` — серверная функция; `likes.js` — её браузерный клиент.
Vercel использует `cleanUrls`: например, `growth.html` доступна по `/growth`.

React, TypeScript, package.json, npm-зависимостей и этапа сборки нет.
HTML/CSS/JS публикуются как есть; API требует среды Vercel и Node.js.
Для просмотра статики: `python3 -m http.server 8000` и `/index.html`.
Этот сервер не поддерживает API лайков и маршрутизацию Vercel без `.html`.

## Проверки перед публикацией

```sh
python3 scripts/check-site.py
node --test tests/likes.test.js
git diff --check
```

Проверка сайта проверяет локальные ссылки, якоря, ресурсы CSS, alt, повторяющиеся
ID, базовые метаданные и синтаксис JavaScript через `node --check`.
Это проектная проверка, а не полный HTML/CSS/WCAG-валидатор. Замечания SEO
выводятся отдельно от ошибок. Lint-фреймворк, typecheck и production build
не настроены и не требуются текущей статической архитектуре.

После изменений интерактивности проверяйте сайт в браузере на узком и широком
экране: навигацию, контакты, CV, Tab/Shift+Tab и Escape в просмотре изображений,
а также страницу 404 на вложенном несуществующем URL.

`scripts/optimize-remaining-images.py` — ручная утилита, требующая Pillow.
Она меняет изображения и ссылки; не запускается при публикации. Исходные
PNG/JPEG сохранены для повторного экспорта. Перед запуском проверьте diff,
после запуска — качество изображений. Её регрессионная проверка:
`python3 -m unittest discover -s tests -p 'test_*.py'` (также нужен Pillow).

`.vercelignore` исключает локальные превью, тесты, инструменты и отчёты из
публикации. Лицензия эффекта остаётся в `assets/light-rays/`.
Результаты технического аудита и оставшиеся рекомендации — в `AUDIT.md`.

## Общие лайки кейсов

`api/likes.js` — Vercel Function с постоянным хранилищем Upstash Redis.
Для запуска подключите постоянную базу Upstash Redis к проекту Vercel и задайте
`UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` (write token) в окружении
Production. Поддерживаются также `KV_REST_API_URL` и `KV_REST_API_TOKEN`.
После настройки опубликуйте новую версию. Секреты не должны попадать в клиентский JS.
Для Preview используйте отдельную базу, чтобы тестовые клики не влияли на сайт.

Каждый браузер получает cookie с анонимным идентификатором на год. Лайк добавляет
идентификатор в Redis Set кейса; повторный клик снимает лайк. Повторная отправка
того же состояния не увеличивает число. Общий счётчик сохраняется после обновлений
сайта и виден всем посетителям. Удаление cookie меняет идентификатор посетителя,
но не удаляет его прежние лайки из общего числа. Это не авторизация пользователей:
один человек может поставить лайк с разных браузеров.

Старые отметки `portfolioLike:<case>:liked=true` переносятся при открытии кейса
в прежнем браузере на прежнем домене. Удалённые данные браузера восстановить нельзя.
При недоступной базе UI показывает ошибку и позволяет повторить запрос;
неподтверждённый клик не отображается как сохранённый.

Проверка: `node --test tests/likes.test.js`.
После публикации проверьте все четыре кейса: лайк, перезагрузка, общий счётчик
в другом браузере, снятие лайка и повтор после потери сети.
Обычный статический сервер не запускает `/api/likes`; нужен Vercel runtime.

Документация: https://vercel.com/docs/functions/runtimes/node-js
и https://upstash.com/docs/redis/features/restapi (атомарные транзакции).
